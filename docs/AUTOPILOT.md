# 自動駕駛（給 David 的白話說明）

停點 P1（2026-10）加的。看這一份就夠用；技術細節在最後兩節。

## 這是什麼

讓 Claude 自己跑完一個階段——偵察、覆述、施工、測試、驗收——中間不用你一直回「批准」「繼續」。它只在該停的地方停下來，而且**每次停下來都會寄信給你**。

**把東西併進正式版（main）這件事，只有你親手輸入的一句話能開門。** 這道門是程式擋的，不是靠 Claude 自律：沒有你的那句話，它用什麼寫法都推不上去。

規格還是由 Cowork 寫；你把規格貼給 Claude，剩下的它自己來。

## 第一次設定（只做一次）

**一、在私人倉庫放寄信用的流程**（三步，都在 GitHub 網頁上做）

1. 打開 <https://github.com/davidjjx/invest-data>，點「Add file」→「Create new file」。
2. 檔名那一格打：`.github/workflows/notify.yml`（打斜線的時候它會自動變成資料夾）。
3. 把 `docs/notify-workflow.example.yml` 的全部內容貼進去，按右上角「Commit changes…」→「Commit changes」。

**二、裝「推送前的檢查」**　請 Claude 執行 `py -3.12 scripts/autopilot_install.py`（它會告訴你裝好了沒）。

**三、測試信**　請 Claude 執行 `py -3.12 .claude/hooks/iw_notify.py test`。一分鐘內你的信箱會收到一封 GitHub 寄的信、手機的 GitHub App 會跳通知。沒收到的話：到 GitHub 右上角頭像 → Settings → Notifications，確認「Participating」有勾 Email。

## 怎麼用

1. **開一個新的工作階段**：資料夾選 `invest-watch`（不是上一層的 `Claude_use`）、模型選 **Fable 5.1**、思考強度選 **Extra high**（輸入框旁邊的思考強度選單，快速鍵 Ctrl+Shift+E）。Max 也不行，只認 Extra high。
2. **輸入**（第一行是指令，下面貼 Cowork 的規格）：

       自動駕駛：A1-4
       （規格全文）

   **第一行要用鍵盤打，不能連同規格整段貼上。** 桌面 App 會把貼上的長文字包成一個區塊；指令詞在區塊裡面，程式不認（貼上的內容不算你親手下的指令）。先打第一行，再把規格貼在下面，一起送出。
3. 畫面出現「**自動駕駛已啟動：A1-4**」。這句是檢查程式回的，不是 Claude 回的——**沒看到這句＝沒有啟動**。整段貼上的話，會出現「（自動駕駛）沒有啟動：…第一行請手打…」；什麼都沒出現，多半是資料夾選錯了。
4. 去做你的事。跑的時候電腦要插電、不能睡著。
5. 收到信之後回到 Claude Code，照信最後兩行輸入就好。

## 你的九句話

都要是**整則訊息**剛好是這句話（或第一行是這句話）。在別的句子中間提到不算——Cowork 的規格裡常常寫著「放行 P1」這幾個字，如果「有提到就算」，貼規格就等於放行了。

| 你輸入 | 效果 |
|---|---|
| `自動駕駛：<階段>`＋下面貼規格 | 啟動 |
| `放行 <階段>` | 開一張一次性的通行證，Claude 才能合併。只有它寄過「做完了、等你放行」的信之後才有效。合併已經上線、只差補文件時，這句是「重開一次補文件的時間窗」 |
| `修改 <階段>：＿＿` | 回去改（冒號後面寫要改什麼）；舊的通行證作廢，改完會再寄一次信。已經合併的階段不能用這句，要退回請用回滾表 |
| `繼續 <階段>` | 從暫停接著做，重新計時。信裡請你看 diff 的話，這句也代表「我看過了」 |
| `放行模型` | 同意用被換上的那個模型繼續；或同意這一輪臨時用 Max 的思考強度（只有 Max 可以，見「模型與思考強度」） |
| `結束自動駕駛` | 解除自動駕駛。合併仍然要你放行 |
| `裁決：<階段>`＋下面貼 Cowork 寫的內容 | 記錄你的裁決——回答 Claude 停下來問的事（規格怎麼解讀、選哪個做法）。它只是紀錄：不解除暫停、不放行、不改任何規則，裡面寫「放行」或「可以改保護檔」也沒有用（2026-10-03 加的，P1-1） |
| `免外部審查 <階段>` | Codex 逾時或不能用、程式已經記下「外部審查未完成」時才有作用：這一次不等 Codex。一次性、綁定當時的 commit、24 小時內有效；有新 commit 或你輸入「修改」就作廢。**只免外部審查**：驗收機要綠、審查代理要批准、合併仍要你另外打「放行」。信、CHANGELOG 與回滾表會寫「本階段未經外部審查（David 親手免除）」（2026-10-04 加的，P2） |
| `驗收機變更 <階段>` | 要改驗收機本身（`verify.yml`、驗收程式、突變的執行器、已知例外清單）時的正規路。**只在一般模式有效**（自動駕駛中打的不算），而且程式已經判定那個 commit「驗收機本身有改」。一次性、綁定階段與 commit；有新 commit 或你輸入「修改」就作廢。有了這句，那個 commit 才能用驗收機的綠；外部審查、審查代理、放行都照舊。信裡會附上驗收機改動的完整 diff（2026-10-05 加的，P2） |

每一句，程式都會在 Claude 做下一個動作之前回頭查對話紀錄：這句話是不是你親手打的。不是的話——有東西冒充你——自動駕駛立刻暫停、通行證作廢、寄信給你。

**寫法差一點的時候會有提示，不會靜悄悄沒反應。** 訊息裡有長得像這九句話的東西、但格式不被接受——整段用貼的、指令不在第一行、前後多了別的字、`放行P1` 少了空白——畫面會出現一行「（自動駕駛）沒有啟動／沒有放行／…：原因。正確的打法」。這一行只是提示：不啟動、不放行、不改任何狀態；照它說的重新打一次就好。你不是要下指令的話，不用理會。代理回報、背景工作通知這類機器送來的訊息不會觸發提示。（2026-10-02 第一次實戰就是整段貼上、畫面沒有任何反應，所以加了這個。）

## 什麼時候會停下來寄信

| # | 情況 | 你會收到 |
|---|---|---|
| 1 | 做完了，準備合併 | 完整的停止報告，最後一行是 `放行 <階段>` |
| 2 | 規格沒寫到、而且有兩種以上做法會影響你看到的結論 | 停止報告，列出選項與 Claude 的看法 |
| 3 | 需要動排程、雲端的更新流程、資料來源、私人倉庫、隱私相關的東西，或自動駕駛自己的檔 | 停止報告 |
| 3′ | 動到了「要先給你看」的檔（見下面） | 停止報告＋ diff |
| 4 | 需要刪資料、改寫歷史資料、動既有的標籤 | 停止報告 |
| 5 | 同一個錯修兩次還是壞的 | 停止報告 |
| 6 | 對外抓資料的次數超出規格的估計，或來源擋它 | 停止報告 |
| 7 | 審查代理審了兩輪還是不批准 | 停止報告 |
| 8 | 需要清單以外的工具或程式 | 停止報告 |
| 9 | 超過 8 小時、用量上限、模型或強度被換 | 短信（用量上限的信會寫額度幾點恢復） |

另外三種「後援」短信，都是程式自己寄的：Claude 沒寄信就停了（「原因不明，請看 Claude Code」）、卡在一個要你按的視窗、工作階段被關掉。

**寄不到的情況**（照實說）：電腦睡著、當機、斷網，或整個 App 被關掉。信寄不出去時內容會留在 `.autopilot/outbox/`、電腦右下角跳通知，之後補寄，補寄的信開頭會寫「這封信晚到了」。

## 停下來之後：暫停、信的等級、怎麼解除（2026-10-03 加的，P1-1）

P1 第一次實戰時，Claude 的一個動作被檢查程式擋下，但程式只擋了那一個動作、沒有讓流程停下，它又做了幾分鐘才自己停。現在改成**程式鎖**：

- 自動駕駛進行中，只要 (a) 任何一個動作被檢查程式擋下、(b) 程式判定的停止條件成立（合併前、保護範圍、審查兩輪、清單以外、時間或用量）、(c) Claude 自己判斷要停而寄了停止報告——hook 就立刻把流程記成「**暫停**」並記下原因。
- 暫停中只准三件事：讀檔與搜尋、在 `.autopilot/runs/<階段>/` 寫報告、寄信給你。其他動作一律擋，而且每擋一次都會記下來。
- 暫停了卻沒寄信就結束：程式自己補寄一封短信。
- 只有你親手打的、而且對得上停下原因的那句話能解除：

| 停下的原因 | 認哪一句 | 不認（只回提示） |
|---|---|---|
| 被檢查程式擋下／程式判定的停止條件／Claude 自己寄了停止報告／請你看 diff | `繼續 <階段>`、`修改 <階段>：＿＿` | `放行` |
| 用量上限、超過 8 小時 | `繼續 <階段>` | `放行` |
| 模型被換 | `放行模型`、`繼續 <階段>`（模型改回來之後） | `放行` |
| 做完了、停在合併前 | `放行 <階段>`、`修改 <階段>：＿＿` | `繼續` |
| 你放行之後、合併途中被擋 | `繼續 <階段>`（通行證不變）、`修改`（通行證作廢） | `放行` |
| 已經合併進正式版、只差補文件（不管中間停過沒有、時間過沒過） | `放行 <階段>`（重開一次性的文件時間窗） | `繼續`、`修改` |
| 任何時候 | `結束自動駕駛`；`裁決：<階段>`（只記錄） | — |

**信的等級**：每封信的標題開頭與內文第一行都有一個等級，由程式依停下的原因決定（Claude 改不了，只能在內文補白話）：

| 等級 | 什麼情況 | 你通常怎麼做 |
|---|---|---|
| 【小事，可以直接繼續】 | 檢查程式擋下了一個動作（例如路徑打錯），那個動作沒有執行、沒有重試、沒有改到任何東西 | 看一眼，輸入 `繼續 <階段>` |
| 【要你決定】 | 規格沒寫到、碰到保護範圍、審查兩輪不過、用量上限、模型被換、擋下之後又重試、沒寄信就停、請你看 diff | 看信裡「你要決定的事」，回 `繼續`／`修改`／`裁決`／`結束自動駕駛` |
| 【要你放行上線】 | 做完了、停在合併前；或已經合併、只差補文件（時間窗過了要你再放行一次） | `放行 <階段>` |

## 信長什麼樣

固定八段、一頁以內、不貼程式碼：一句話／你要決定的事（最多 3 件）／做了什麼／怎麼自己看／名詞解釋／要繼續／要修改／不確定就轉給 Cowork。標題開頭的【等級】與內文第一行「等級：…」是程式加的。

最後兩行是程式加的，不是 Claude 寫的：

- `本階段使用模型：…／思考強度：…／中途是否切換：…`
- `安全檢查：…`——正式版上，從上次放行到現在，有沒有「不是排程的資料更新、又沒有放行紀錄」的變更。只改資料、但不是排程固定寫法的推送，也會列出來。

信開在私人倉庫 `invest-data` 的 issue 裡，只有你看得到。你放行、合併完成之後，那個 issue 會被留言「已放行」並關掉。

P2 之後每封信還多三行，也是程式加的：

- `驗收機：綠／紅／沒有紀錄（執行紀錄的連結）`
- `外部審查（GPT）：Codex／免除／未完成；重大 n 條；採納 n、不採納 n（PR 的連結）`
- `流程檔檢查：…`——自上次停止信以來，有沒有任何分支新增或修改了 `.github/workflows/` 裡的檔（做法：寄信前先向 GitHub 更新所有分支的位置，記下每個分支上每個流程檔的內容編號，跟上一封信存的那一份、以及現在的正式版比；跟正式版一樣的不算、上次報過的不重報）。這個階段的分支改了驗收機本身時，信裡另外會有一行 ⚠ 與完整的 diff。

## 第三方審核：驗收機與 Codex（2026-10-04 加的，P2）

P1-1 的報告把「14 個檔」寫成「24 個檔」。審查代理跑在同一個工作階段、用同一個模型、看的是 Claude 整理給它的報告，測試數字也是 Claude 自己回報的。P2 加兩個**施工的一方改不了**的第三方；每個階段的線變成：

施工 → 驗收機 → GPT 外部審查 → iw-reviewer → 你放行

**驗收機**是 GitHub 的電腦（GitHub Actions）。Claude 每次把分支推上 GitHub，它就從**實際的那個 commit** 重跑全套測試、隱私掃描、擋字串、docs 大小上限、突變對照（把保護改壞一處、測試要紅），而且把對外連線封起來、記下每一個對外請求——對臺灣銀行的請求出現任何一次就紅，「台銀 0」由它證明。凡是會執行分支上程式碼的步驟都在封鎖裡跑：全套測試、每一片突變、跟正式版比的那一步；每一段的紀錄合起來判定。被系統層擋下、只留下 IP 的連線（例如測試叫了別的程式去連）也算紅，因為看不出是連誰。另外，commit 訊息一推上公開倉庫就收不回來，驗收機事後才看已經來不及，所以從 Claude Code 推送之前，推送前的檢查會先把每一筆新 commit 的訊息過一次隱私掃描（個人資料的字樣、權杖、電子郵件、本機路徑），命中或掃描器讀不到就擋。每一段在把結果交出去之前先過隱私掃描，只帶判定需要的檔；完整的詳細輸出與瀏覽器的紀錄不上傳，掃描命中時只記是哪個檔、不把命中的字寫出來。它會跟正式版比：測試數與突變數不准變少，被刪或被改的測試逐條列出，動到保護範圍的檔也列出來。結果是一份綁定 commit 的檔（artifact），Claude 的報告數字要取自它、旁邊附本機的數字；對不上就是「要你決定」。

- 判定一律用正式版（main）上的驗收程式。
- **驗收機本身怎麼不被施工的一方改掉（照實說）**：原本的設計是「流程檔由你在 GitHub 網頁貼、Claude 的憑證沒有 `workflow` 權限所以推不動」。2026-10-04 實測這個假設**不成立**：這台電腦上 git 與 gh 存的 GitHub 憑證都有 `workflow` 權限，Claude 推一個含新流程檔的丟棄分支，GitHub 收了——這台電腦的憑證推得動流程檔。換憑證的代價太高（你自己在終端機緊急退回也會被拒收、gh 的權杖也要一起改、會影響這台電腦上所有倉庫），所以改成**由程式比對來擋**：
  - 寄「可以合併」的信、你放行、合併之前，程式各用 git 比一次：那個 commit 上的 `verify.yml`、驗收程式（`scripts/verify_ci.py`）、突變的執行器與已知例外清單，跟正式版上的內容是不是一模一樣。只要有一個不一樣，驗收機的綠一律不算（它看的是 git 的內容編號，不是 GitHub 上那次執行自己說的）。
  - 只認真正的那一次驗收：流程檔的路徑是 `.github/workflows/verify.yml`、執行的 commit 就是那一個、由 push 觸發；結論與數字都從那一次執行的結果檔讀。只是名字對得上的檢查、手動觸發的執行，一律不算。
  - 自動駕駛期間，檢查程式擋下所有寫入 `.github/workflows/`、驗收程式、突變與已知例外清單、`AGENTS.md` 的動作；推送前的檢查擋下所有動到這些檔的推送。不論哪種模式，用 GitHub 的 API 寫入或刪除檔案內容一律擋。
  - 每封停止信有一行「流程檔檢查」，寫明自上次停止信以來有沒有任何分支新增或修改了流程檔。
  - 真的要改驗收機本身：只能在一般模式做，而且要你親手輸入「驗收機變更 <階段>」（見「你的九句話」）；信裡會附上完整的 diff。P2 是建立期，流程檔由 Claude 推，合併之後就照上面鎖住。
- **封鎖沒設成就是紅**（2026-10-06 的裁決，取代 10/4 的「缺系統層不紅、只寫層級 2／3」）：全套測試與每一片突變都要有系統層的封鎖（另一個使用者＋防火牆），IPv4 與 IPv6 的規則都要有；哪一段缺了，那一次驗收就是紅。結果檔照樣寫每一段的層級；紅的原因以「封鎖沒設成」開頭，跟「測試紅」分開寫，一看就知道是哪一種。這種紅的對策是**重跑**，不是接受比較弱的證據。為了少一點誤紅，建立測試用的使用者與設防火牆那幾步的逾時從 120 秒放寬到 300 秒，失敗之後自動再試一次（10/6 凌晨 GitHub 的執行機很慢，有兩片就是卡在建使用者逾時）。
- **重跑驗收**（`gh run rerun`）：兩種模式都可以用，但有範圍，由檢查程式擋——只能對「流程檔是 `verify.yml`、執行的 commit 是現在分支最頂端那一個、由 push 觸發」的那一次執行；同一個 commit 最多重跑 2 次；每一次程式都記下來，報告要寫是哪一次、為什麼。重跑 2 次還不是每一段都綠、封鎖 3／3，就停下來寄「要你決定」。算數的是最後那一次嘗試的結果（結果檔是第幾次嘗試寫的，程式會跟 GitHub 對）；程式認的仍是同一次執行。信裡「驗收機」那一行會寫重跑過幾次。
- **執行機的版本寫死 `ubuntu-24.04`**，不用 `ubuntu-latest`：GitHub 從 2026-10-19 到 11-19 分批把預設換成 Ubuntu 26.04，三層封鎖不可以跟著不知不覺地變。升級見最後面的「待辦」。
- 紅＝GitHub 會寄你一封「Run failed」的信。那代表驗收機抓到問題；自動駕駛另外會寄白話的信。
- 它只讀（`contents: read`）、沒有任何密鑰、不推任何東西、不寫 issue 或 PR；只在推 `feat/` 分支與 `stop` 標籤時跑，**main 有推送時不跑**，所以黃金排程與資料更新一個字不用改、也不會被它擋。

**外部審查員**是 OpenAI 的 Codex 程式碼審查，用的是另一個 ChatGPT 帳號的方案（不是 David 的帳號；只由帳號持有人本人登入、設定）。Claude 本機全綠之後開一個 PR（`feat/<階段>` → `main`），Codex 自動讀 PR 的實際改動、只挑重大問題（P0／P1），用繁體中文寫意見（審查準則的公開版在倉庫根目錄的 `AGENTS.md`）。Claude 要逐條回覆「採納並修」或「不採納＋理由」，寫在它自己的報告資料夾（`03_第三方審查.md`），**不在 PR 上回覆、不爭論、不 resolve、不刪、不隱藏**——程式擋著。

- 只認「Codex 的機器人帳號、針對 PR 最新那個 commit」發出的 review；公開倉庫誰都能留言，別人的留言一律忽略、在信裡列出。「沒留言」永遠不算通過。
- **審到什麼時候算完**（2026-10-06 的裁決；兩個條件都要）：
  1. 最新的 commit 經 Codex 審過（下面的訊號 A 或 B），而且它對這個 commit 沒有提 P0。有 P0 就一定要修：修好、推上去、再請它審。
  2. 這個 PR 上 Codex 提過的**每一條**意見都在回覆表裡有一列——不分是哪個 commit 提的、GitHub 有沒有把那則留言跟著移到新的 commit。原本只算最新 commit 的，舊的再推一次就不用回了。針對最新 commit 的意見，回覆不能直接寫「採納並修」：要修它，得有一個更新的 commit，推上去之後再請 Codex 審那個新的 commit。
- **「不採納」的規矩**：P0 不能不採納，一定要修。P1（沒標等級的從嚴當 P1）要不採納，理由欄只能寫「Cowork 裁決：<檔名>」或「延後到 <階段>，Cowork 裁決：<檔名>」，而且那個檔真的在這個階段的報告資料夾裡；沒有 Cowork 的裁決檔，程式一律當成還沒回覆。信裡「外部審查」那一行會把指到的檔名列出來。延後的要寫進這份文件最後面的「待辦」。
- **輪數上限**：開 PR 時自動審的算第 1 輪，之後每留一則 `@codex review` 算一輪。一般的階段 4 輪；P2 是 6 輪（建立期，意見多）。數字寫在設定檔。到了上限程式就不再留言；還沒達成上面兩個條件的話，停下來寄「要你決定」，把剩下的意見列成表。**上限不是自動放行**。
- 開 PR 之後又加的 commit 如果動到新的保護檔，要用 `pr edit` 重新送一次內文（程式會重新列「動到的保護範圍檔」那一段）；寄「可以合併」的信之前，程式會拿現在的改動跟 PR 內文那一段再對一次，漏了就不寄。
- 回覆表很嚴：回覆那一欄只能寫「採納並修」或「不採納」，一字不差；最後一欄（理由或修在哪）不能空；同一條意見不能有兩種回覆。寫成「尚未採納」「部分採納」這類，程式一律當成還沒回覆。
- Codex 的意見有兩種放法，程式兩種都讀、都要逐條回覆：釘在某一行上的行內留言；以及寫在 review 本文裡的（釘不到改動行上的意見會放這裡，一行檔案連結加一行等級徽章）。留言超過一頁（100 則）時一頁一頁讀完；任何一頁讀不到就當成查不到。
- **Codex 審完的訊號有兩種**（2026-10-06 的裁決；Codex 的實際行為以 2026-10-05 這個倉庫 1 號 PR 上看到的為準）。兩種都要綁最新的 commit：
  - 訊號 A（有意見）：機器人帳號針對 PR 最新的 commit 發出的 review。意見只記錄、逐條回覆，不當作通過的依據。
  - 訊號 B（沒有意見）：Codex 沒有意見時**不發 review**，只在 PR 上按 👍，並把它自己那則「Codex Review Summary」留言更新。程式認的是那則留言的表格：Code Review 那一列的 Status 是 Completed、Commit 欄的短 sha 跟最新的 commit 對得上、完成時間晚於最後一次推送，也晚於最後一則 `@codex review` 留言（第一次自動審查則要晚於開 PR）。符合就記「外部審查完成、0 條意見」，信裡會寫明是這一種。「最後一次推送」的時間取驗收機由 push 觸發那一次執行的建立時間（GitHub 記的，不是本機說的）；最新的 commit 沒有那樣的執行，訊號 B 一律算「未完成」。
  - 不算訊號的：👍 與 👀 表情（不綁 commit）、不是機器人帳號發的留言（內容再像也不算）、Commit 欄是舊的 sha、Status 不是 Completed、一般留言裡出現 Completed 字樣。
  - 同一個 commit 兩種訊號都有時，以 review 的意見為準。
  - Codex 那張表的欄位如果跟上面不一樣（少了 Commit 欄、Status 的用字變了、讀不出完成時間），程式一律判定「外部審查未完成」，寄「要你決定」的信，不自己猜。10/4 的版本假設「沒問題也會發一則 review」，那個假設不成立。
- 合併方式不變：你放行之後 Claude 照舊在本機 `--no-ff` 合併、推上 main，PR 會自動變成已合併。**不用 GitHub 網頁上的合併按鈕**。
- Codex 的用量是獨立的一類（Code Review usage），不吃帳號持有人平常用的 Codex 額度（官方定價頁）。
- PR 的標題與內文只寫改了什麼、不放規格原文，程式先過隱私掃描才送出（公開倉庫的 PR 人人看得到）。
- Codex 的 GitHub 連結只裝在 `invest-watch`，絕不裝到 `invest-data`；誰都不叫它改程式（不用 `@codex fix`、不開雲端任務）。

**關卡（程式擋，不靠約定）**：寄「要你放行上線」的信之前，程式查這幾件事——驗收機對這個 commit 是綠的；外部審查完成（Codex 審過最新的 commit 而且沒有 P0，或你免除）；這個 PR 上 Codex 提過的每一條意見都有回覆（不分是哪個 commit）；沒有 P0 被判不採納；P1 被判不採納的都指得到 Cowork 的裁決檔。缺一件信就寄不出去。還沒有裁決的，改寄「要你決定」給你與 Cowork 裁決。你放行時、合併前，程式各再查一次驗收機；查不到（例如 GitHub 連不上）就擋，不當成通過。自動駕駛與一般模式都一樣，沒有任何跳過審查的選項（P1-1 時一般模式有的那個選項已經拿掉）。

**Codex 不能用時（額度用完、設定被關、等 60 分鐘沒審）**：程式記下「外部審查未完成」，Claude 寄「要你決定」的信，給你兩個選項——等（之後打「繼續 <階段>」，重新請 Codex 審）、或打「免外部審查 <階段>」。原本規格要用 GitHub Models 的免費 GPT 當備援，但 GitHub Models 已於 2026-07-30 退役，沒有免費、不用密鑰的備援可用，所以改成這一句。連續兩個階段都免除，信裡會提醒請帳號持有人檢查 Codex 的設定。

## 三道保護

1. **動作執行前的檢查。** Claude 每次要執行指令、改檔、叫子代理之前，Claude Code 會先把「它打算做什麼」交給一支檢查程式；檢查程式說不行，動作就不會發生。它會把一長串指令拆開逐段看，`cd … &&`、`sh -c '…'`、用 PowerShell 包一層都一樣。看不懂的寫法一律擋。
2. **推送前的檢查。** 裝在 git 裡面。不管指令怎麼寫，只要從這台電腦的這個倉庫推東西，git 自己會先問它；它看的是「實際要推上去的內容」。有通行證時，必須剛好是「以現在的正式版為底、把你放行的那個版本合併進來」的那一個合併，其他形狀都擋。它還會自己算一次「原封不動合併」的結果來比對：合併的時候夾帶別的改動、或有衝突是手動解的，都推不上去（有衝突就停下來寄信給你）。
3. **保護檔本身不能改。** 檢查程式、設定、清單、審查準則都在主目錄的 `.claude/` 裡，生效的永遠是正式版上的那一份。要改它們，得開一個階段、在分支上改、你放行合併之後才生效。

**沒有通行證也能推上正式版的，只有一種：** 筆電的黃金排程——只動 `data/latest.json`、`data/sources/local.json` 與三個黃金的歷史檔，不是合併，而且不是從 Claude Code 裡推的。所以既有的排程一個字都不用改。

**平常（不在自動駕駛）也會擋的寫法。** 只要工作階段開在 `invest-watch`，下面這些 Claude 都做不了；被擋到時它會告訴你原因。檢查程式只管 Claude——你自己在終端機下指令不受影響。

- 合併或推上正式版、強推、刪或移動標籤、改寫歷史（沒有通行證時）。
- 它不認得的 git 指令（自訂別名、外掛、底層的傳輸指令）；會讓 git 另外執行一個程式的選項。
- 看不出實際執行什麼的寫法：拿變數或指令的輸出當程式名稱、大括號展開、把指令用管線餵給 shell、替指令另外取名字。
- 改保護檔、git 的設定與 hook、shell 的啟動檔；刪除、搬動或整個複製主目錄與它的 `.claude`。
- 新增或修改排程、在別的身分或別台機器上執行指令。
- 讀取登入憑證與瀏覽器的資料夾（本站設定頁把 PAT 存在瀏覽器裡）。
- 用 GitHub 的 API 做任何寫入；啟用或停用雲端的流程；**從 main 以外的分支執行流程**（`gh workflow run --ref <分支>`）——那等於讓還沒放行的流程拿著倉庫的寫入權限跑。以前「先從分支跑探測流程」的做法，以後要你自己在 GitHub 網頁上按「Run workflow」選分支。

第一版是「把危險的寫法列出來、其他放行」。請一個獨立的審查代理專門找漏洞，找了三輪：第一輪 6 類（例如 `git send-pack`——git 底層的推送，不經過第二道）、第二輪 4 類、第三輪 3 個較小的缺口，都補了。現在的原則是：看不懂的、不認得的，一律擋。第三輪的結論是「沒有找到新的方法可以動到正式版、改寫歷史或移動標籤」；剩下的風險見下面「擋不住的事」。

**自動駕駛期間另外多一條：不執行直接寫在指令裡的程式碼**（`python -c "…"`、用 heredoc 餵程式碼）。檢查程式看不到程式碼裡面做了什麼，所以只准執行腳本檔——腳本檔至少留得下來，審查代理與你之後看得到。

- 啟動時畫面會多一行：「這個階段的分支在啟動之前就已經改了 N 個動不得的檔」。
- 停止報告最後會用 ⚠ 列出這些檔，讓你放行之前看得到。
- 自動駕駛期間它們只要再被動到（就算是用腳本偷改，寄信前程式會比對內容），「做完了、等你放行」的信就寄不出去。
- 不用自動駕駛、你全程在場做的階段也一樣：動到這些檔可以，但信裡一定寫出來。

## 審查代理

另一個獨立的 Claude，叫 `iw-reviewer`。它看不到施工那邊的對話，只能讀檔、不能改任何東西。每個階段它審兩次：覆述一次、驗收一次（連要寄給你的信一起看）。它的結論是程式記下來的，不是 Claude 轉述的；沒有它對「現在這個版本」的批准紀錄，「做完了、等你放行」的信寄不出去。

## 擋不住的事（照實說）

1. **把危險的動作藏在自己寫的腳本裡再執行。** 指令文字裡看得到的都擋；第二道連腳本裡的 `git push` 也擋得住。擋不住的是：腳本裡用 git 底層的傳輸指令（不經過第二道）、另外複製一份倉庫再從那一份推、直接呼叫 GitHub 的 API、或在腳本裡改保護檔。這需要蓄意、分好幾步、把字串藏起來才做得到，不是手滑會發生的事，但程式上不是不可能。補救：下一封信的「安全檢查」那一行會寫出來；下次開工作階段會檢查保護檔有沒有被動過。要完全擋住得靠作業系統層級的隔離（Windows 沒有、MacBook 有）。
2. **電腦睡著、當機、斷網時沒有信。**
3. **工作階段開在別的資料夾**時，第一道與通知都不會載入，只剩第二道。所以自動駕駛與放行都要在資料夾選 `invest-watch` 的工作階段做。
4. **模型被換掉之後的第一個動作可能來不及擋**（對話紀錄會慢一兩秒寫入），第二個動作一定擋。
5. **「是不是你打的」用到一個官方文件沒寫的欄位。** Claude Code 改版如果拿掉它，你的指令詞會變成一律不被承認（寧可擋錯），到時候要修。
6. **判斷類的停止條件**（2、4、5、6）要不要停，程式判不出來，靠 Claude 與審查代理；但只要它寄了停止報告、或任何一個動作被擋下，程式就把流程鎖住（P1-1 加的），不再靠 Claude 自己停。
7. **讀檔與搜尋不經過檢查程式**（每讀一個檔都檢查會太慢）。存登入憑證與瀏覽器資料的幾個位置，改用 Claude Code 自己的拒絕規則擋（`.claude/settings.json` 的 `permissions.deny`）。
8. **這台電腦的 GitHub 憑證推得動流程檔**（2026-10-04 實測）。所以「Claude 改不到驗收機」不是 GitHub 擋的，是程式擋的：寄信、放行、合併前比對內容，自動駕駛期間擋寫入與推送，每封信一行「流程檔檢查」。被改過的流程檔在 GitHub 上照樣會跑、照樣可能顯示綠燈——那個綠程式不認。
9. **檢查程式是「看指令的字」來判斷的，不是把 Claude 關在籠子裡。** 審查找過三輪漏洞、都補了，但沒有人能保證沒有下一個。真正的底線是第二道（看實際推送的內容）與每封信的「安全檢查」。
10. **你放行的那個版本本身。** 程式保證「合併進去的就是你放行的那個版本、一個字不多」，但那個版本裡面寫了什麼，靠的是審查代理、信裡的說明、與你自己看。「做完了、等你放行」的信寄出之前，程式會再確認三件事：主目錄沒被動過、保護檔跟放行過的版本一樣、而且是跟遠端真正的正式版比過才說「這個分支改了哪些檔」。

## 名詞解釋

- **hook**：Claude Code 在 Claude 做每個動作前後自動執行的程式。不是 Claude 在執行，它也改不了。
- **通行證**（規格裡叫憑證）：你輸入「放行 <階段>」時程式寫下的一筆紀錄，綁定階段與要合併的那個版本。24 小時內有效，合併一次、補文件一次。
- **worktree**：同一個倉庫的另一個工作資料夾。施工都在那裡，主目錄留在正式版、乾淨，筆電的排程才能照跑。
- **diff**：一個檔改了哪些行。
- **標籤**：在某個版本上貼的名字（例如 `stopA1-4`），之後找得回來、退得回去。

## 技術摘要

| 事件（Claude Code 的 hook） | 做什麼 |
|---|---|
| `PreToolUse` | 第一道保護：`.claude/hooks/iw_guard.py`。讀檔與搜尋不經過它。自動駕駛期間擋下任何動作，同時把流程記成暫停（`state.json` 的 `pause`） |
| `UserPromptSubmit` | 認你的九句話；只有這裡會開通行證、重開文件的時間窗、記錄裁決、記下免外部審查與驗收機變更（放行時再查一次驗收機） |
| `PermissionRequest` | 自動駕駛期間，要跳「等你按批准」的視窗時一律代為拒絕（停止條件 8） |
| `PostToolUse`（Agent）、`SubagentStop` | 記審查代理的結論與它實際用的模型 |
| `Stop`、`StopFailure`、`Notification`、`SessionEnd` | 後援信 |
| `ConfigChange` | 工作階段進行中改設定檔不會生效 |
| `PreModelSwitch`、`PostModelSwitch` | 模型被換的紀錄與暫停 |
| `SessionStart` | 檢查保護檔有沒有被動過；壓縮對話後提醒目前的狀態 |

hook 的指令都寫成「任何失敗都以結束碼 2 結束」。原因：官方文件說只有結束碼 2 會擋，找不到腳本、程式當掉、逾時預設都是放行。

測試：`scripts/test_autopilot_*.py`（守門、推送前的檢查、流程、設定一致性、指令解析）與 `scripts/test_verify_ci.py`（驗收機的判定、比對、封鎖），全部離線；驗收機與 Codex 的回答在測試裡用一個 JSON 檔替身（`IW_TEST_FAKE_GH`），不連 GitHub。

**驗收機怎麼封鎖對外連線**（三層，結果檔會寫每一段實際生效幾層）：另一個使用者＋iptables 與 ip6tables（只擋那個使用者的對外封包，IPv4 與 IPv6 各一份；執行機自己跟 GitHub 的連線不受影響）、Chrome 的名稱解析規則（所有名稱都查不到、同時記下它查過什麼）、Python 的 socket（任何對外的名稱解析與連線都拒絕並記下）。少了第一層照樣跑完、照樣寫層級，但那一次驗收判紅，原因寫「封鎖沒設成」（2026-10-06 的裁決；10/4 的版本是不紅）。Chrome 自己的背景連線（更新、安全瀏覽）列出來、不算紅；名單在 main 上的驗收程式裡。

**保護的版本**：`.claude/autopilot/config.json` 的 `protectionVersion`（現在是 P2）。合併進 main、主目錄快轉之後新版就直接生效——hook 每個動作都新開一個程序讀主目錄的檔，不用安裝、不用重開；只有 `.claude/settings.json`（hook 掛在哪些事件）要開新的工作階段才生效。`py -3.12 .claude/hooks/iw_notify.py status` 會印版本；`py -3.12 scripts/autopilot_install.py --check` 看入口與保護檔在不在（這台電腦請一律用 `py -3.12`，不要用 `python`——見下面的測試環境）。

**合併固定分兩個指令**：先單獨建合併用的 worktree，確認在了，再用第二個指令進去合併（2026-10-02 兩步寫在同一段被擋——檢查程式在執行前就把整段看完，那時候資料夾還不存在）。合併推上去之後**立刻**推文件那一筆；中途停了或 60 分鐘過了，狀態維持「已合併、等補文件」，你再輸入一次「放行 <階段>」就重開一次性的時間窗。早先階段的文件併進這一筆時（P1 的回滾表併進 P1-1），用 `iw_notify.py finish-docs --stage P1 --merged-into P1-1` 把早先的階段結案，之後「放行 P1」不會再開任何時間窗。

**測試環境寫死在設定裡**（`.claude/autopilot/config.json` 的 `testEnv`；每次啟動、繼續、修改、放行、壓縮對話之後，hook 都照它告訴 Claude 一次，不靠它記得）：

- Python 一律 `py -3.12`（專案排程用的版本）。這台電腦打 `python` 會跑到另一個版本，那個版本沒裝 `requests`，幾十條測試會假紅。
- 瀏覽器那幾組一律用 Chrome：先設環境變數 `IW_BROWSER` 指到 Chrome。Edge 的無頭模式在這台電腦上會回空白頁，那幾組一開始就錯。
- 具名字串的隱私掃描另外要兩個環境變數，值是這台電腦的私人路徑，不進版控：寫在主目錄的 `.autopilot/local-env.txt`。沒有那個檔時那一條會略過，報告裡要照實寫。
- 換電腦（例如 MacBook）時要改 `testEnv`；它是保護檔，改它要經過放行。
- 查版本的指令（`python --version`、`py -3.12 --version`、`py --list`、`command -v py`、`which python`）是唯讀的，任何時候都不會被擋。

## 依據（2026-10-01 查的官方文件與實測）

官方文件 <https://code.claude.com/docs/en/hooks>、`/settings`、`/permissions`、`/permission-modes`、`/sub-agents`、`/skills`、`/model-config`：

- hook 的設定只從工作階段開的那個資料夾載入，沒有上下層備援。
- 只有結束碼 2 會擋；`PreToolUse` 的 hook 逾時不擋。
- 權限規則「不是安全邊界」，要硬擋就用 `PreToolUse` hook 檢查整段指令。
- `UserPromptSubmit` 的輸入沒有「是不是人打的」的欄位。
- `model`、`effortLevel` 是新工作階段的預設值；`switchModelsOnFlag: false` 讓訊息被標記時暫停而不是自動換模型。
- 子代理的模型：呼叫時帶的參數會蓋過它檔案裡寫的，所以檢查程式不准帶。
- Auto 模式預設允許推上正式版（所以一定要自己擋）；沙盒不支援 Windows。

桌面 App 上實測（Claude Code 2.1.284）：專案資料夾的 hook 會載入、新增或修改設定檔會即時生效；結束碼 2 擋下、結束碼 1 不擋；子代理的動作也經過 hook；代理回報的訊息也會觸發 `UserPromptSubmit`（外面包著標籤）；對話紀錄約慢 0.5～1.5 秒；每個動作多約 1 秒；Windows 上要自己用 UTF-8 輸出，不然中文會變亂碼。
