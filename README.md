# InvestWatch — 個人理財監控儀表板

每天自動抓黃金、台股、美股、原油、比特幣與匯率的公開行情，算成幾個看得懂的指標，
放在一個手機和電腦都能開的網頁上。

**網址**：https://davidjjx.github.io/invest-watch/

---

## ⚠ 先講清楚兩件事

**一、這裡沒有任何投資建議。**
網站上的「相對低檔區／中性／相對高檔區」燈號，只是把 RSI、均線位置、52 週區間百分位
這些客觀數字做分類。這些規則**沒有經過任何歷史回測驗證**，不構成投資建議，也不保證
未來走勢。實際投資決定與盈虧由使用者自行負責。

**二、這個公開倉庫裡沒有任何個人資料。**
這裡只有公開的市場價格。持倉、成本、進場紀錄等個人資料一律不進這個倉庫
（Phase 3 會存在瀏覽器本機或使用者自己的私人倉庫）。

---

## 它是怎麼運作的

```
GitHub Actions（雲端定時工讀生）
  每天台北時間 10:00 / 13:00 / 15:00
      │
      ├─ 跑 scripts/fetch_data.py 去各官方網站抓牌價
      ├─ 更新 data/latest.json（最新報價）與 data/history/*.json（日線歷史）
      └─ 自動 commit + push 回這個倉庫
                                    │
                                    ▼
                       GitHub Pages 把倉庫變成網站
                       你用手機或電腦開網址就看得到
```

重點：**更新完全不需要你的電腦開機**，全部在 GitHub 的主機上跑。

前端不會直接連台銀／證交所——那些網站擋跨網域請求（CORS），所以一律由 Actions 上的
Python 先抓好存成 JSON，網頁只讀自家倉庫的靜態檔。

## 檔案結構

```
invest-watch/
├─ index.html            儀表板（首頁）
├─ history.html          歷史頁（Phase 2）
├─ records.html          我的紀錄（Phase 3）
├─ settings.html         設定（Phase 3 / 4）
├─ css/style.css         深色系樣式，手機優先 RWD
├─ js/
│   ├─ indicators.js     指標計算（MA / RSI / 百分位…），純函式
│   ├─ charts.js         畫圖（迷你走勢線 + Chart.js 大圖）
│   └─ app.js            頁面邏輯
├─ lib/chart.umd.min.js  Chart.js 4.4.4，下載到本地，不依賴 CDN
├─ data/
│   ├─ assets.json       監控清單設定檔 ← 要增減標的只改這一個檔
│   ├─ latest.json       每次更新寫入：所有標的的最新報價與狀態
│   └─ history/<id>.json 各標的日線歷史（最多 400 點）
├─ scripts/fetch_data.py 抓資料腳本（只用 requests）
└─ .github/workflows/update-data.yml   排程設定
```

**分層原則**：資料層（`scripts/`）、設定（`data/assets.json`）、呈現層（`js/`、`css/`）
互相分離。前端不用任何框架，純 HTML + CSS + JavaScript，所有路徑都是相對路徑。

## 自己動手跑

```bash
# 安裝套件（只需要一次）
pip install requests

# 抓一次資料
python scripts/fetch_data.py --slot manual

# 只抓其中幾項（測試用，其他項會沿用上次結果）
python scripts/fetch_data.py --only gold_twd,fx_cny

# 本機開網站看看
python -m http.server 8765
# 然後瀏覽器開 http://localhost:8765
```

想手動觸發雲端更新：GitHub 倉庫 → **Actions** 分頁 → 左邊選「更新市場資料」→
右邊 **Run workflow** → 按綠色按鈕。

## ⚠ 已知限制：台銀資料在雲端抓不到

2026-08-31 實測發現：**臺灣銀行的網站會擋掉 GitHub Actions 的連線**。

台銀用了機器人防護（Akamai），對「資料中心 IP」特別嚴格。GitHub Actions 的主機
就在資料中心裡，實測每個網址連試 8 次全部只拿到驗證頁；同一支程式在家用電腦上跑
卻一次就過。

受影響的是這 5 項：黃金存摺 TWD、黃金存摺 CNY、實體黃金條塊、美元/台幣、人民幣/台幣。
證交所與 Yahoo 的 7 項不受影響，雲端排程照常更新。

### 解法：家用電腦負責補抓（已設定好）

家用電腦上已建立 Windows 排程工作 **`InvestWatch-UpdateData`**，每天 **10:05 / 13:05 / 15:05**
自動執行 `scripts/update_local.ps1`：抓全部 12 項 → 有變動就 commit → 推回 GitHub。
電腦關機而錯過的時段，會在**下次開機時自動補跑**（`StartWhenAvailable`）。

所以實際上是兩邊分工：

| 誰 | 什麼時候 | 負責哪些 |
|---|---|---|
| GitHub Actions（雲端） | 每天 10:00 / 13:00 / 15:00 | 台股 3 項 + 海外 4 項（一定會更新，不需開電腦） |
| 這台電腦的排程工作 | 每天 10:05 / 13:05 / 15:05 | 全部 12 項，含台銀那 5 項（要電腦有開機） |

若某個時段電腦沒開，網站上台銀那 5 項會誠實顯示「更新失敗＋失敗時間」，
其餘 7 項照常更新。

**查看／管理排程**（PowerShell）：

```powershell
Get-ScheduledTaskInfo -TaskName "InvestWatch-UpdateData"
```

手動跑一次：

```powershell
Start-ScheduledTask -TaskName "InvestWatch-UpdateData"
```

不想要了就移除：

```powershell
Unregister-ScheduledTask -TaskName "InvestWatch-UpdateData" -Confirm:$false
```

執行紀錄在 `scripts/update_local.log`（不進倉庫）。

> 這一點與 PLAN.md 第 7 章的假設不同——規劃書當時是在家用電腦上實測通過的，
> 沒有測到雲端環境。
>
> 順帶一提，中國信託不能拿來替代：它的網站有 JS 型機器人驗證（回 HTTP 202 加一段
> 混淆過的 JavaScript），連在家用電腦上都拿不到資料，比台銀更嚴。玉山銀行的匯率
> 頁面倒是能直接解析，若未來想讓匯率也能在雲端更新，那是可行的方向——但那會變成
> 看玉山的牌價，不是台銀的。

## 資料壞掉的時候會怎樣

這是刻意設計過的（誠實原則）：

- 某個來源抓失敗 → **保留舊的歷史檔不動**，在 `latest.json` 把該標的標成
  `status: "error"` 並記下錯誤訊息與失敗時間。
- 網頁上該張卡片會顯示紅框 **「⚠ 這一項資料更新失敗」＋ 失敗時間**，
  舊價格只會出現在標明「上次成功」的灰字裡，**不會冒充成現價**。
- 其他標的照常顯示，整個網站不會因為一個來源壞掉就掛掉。
